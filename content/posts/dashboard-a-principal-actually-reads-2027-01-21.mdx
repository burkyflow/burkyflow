A dealer principal gets a dozen dashboards: the DMS, the CRM, the website vendor, the digital retailing tool, the call tracking, the reputation tool, the automation platform. Most are opened once. The one that gets read every Monday has three properties: revenue is at the top, every number is defined, and it fits on a page. Here is what goes on it.

## Revenue first

The top line answers the only question that matters: what did this produce?

- **Revenue attributed this month**, split by source: service appointments, F&I products, vehicle sales, refinance or buyout deals.
- **Same number last month and the same month last year.**
- **Attribution rule stated on the page:** the customer booked, replied, or arrived through a tracked conversation, and the revenue is from the DMS.

If revenue cannot be shown with that rule, the dashboard is not ready.

## The four-step funnel

Below revenue, the lead funnel split into its steps, because the total hides the leak:

1. Leads by source
2. Contact rate, with the share contacted under five minutes
3. Appointment rate on contacted leads
4. Show rate, and close rate on shows

Each with last month beside it. A principal can see in ten seconds which step moved.

## The recovery programs

One row per active funnel, same columns for each:

| Program | Contacted | Replied | Booked | Sold | Revenue |
|---|---|---|---|---|---|
| Service reminders | | | | | |
| Warranty-end service contracts | | | | | |
| Declined repairs | | | | | |
| Refinance-ready | | | | | |
| Lease maturity | | | | | |

Same scale for every program, so the principal can compare them and decide which to expand.

## The health numbers

A small block that says whether the system is behaving:

- **Contact load:** messages per customer per month. Rising load with flat results means the system is annoying people.
- **Opt-out rate** per thousand messages.
- **Reconciliation:** appointments reported versus appointments in the CRM; shows reported versus shows in the DMS. Within tolerance, or not.
- **Response time:** median time from lead to real response, by hour band.

## What stays off

- Messages delivered, opens, clicks. Activity, not outcomes.
- Vanity totals since launch.
- Anything not defined on the page.
- Charts that need explanation.

If a number cannot be explained in one sentence, it does not belong on the principal's page. It can live on an operational page for the BDC manager.

## Building it

The dashboard is only as honest as its sources:

- **Revenue and shows from the DMS.** Never from the automation platform's estimates.
- **Conversations and appointments from the CRM**, with the counting rules from the previous post in this series enforced in the data, not in the chart.
- **Reconciliation automated**, so the tolerance check runs monthly without anyone pulling exports.

A [CRM and reporting layer](/services/crm-lead-systems) built on DMS data produces this page as a standing report. The [workflow platform](/services/workflow-automation) behind it refreshes it nightly.

## How it gets used

- **Monday:** the principal reads the page. Revenue, funnel, programs, health. Two minutes.
- **Monthly:** the BDC manager and the vendor walk through the reconciliation and the program table. Expand what works, fix or stop what does not.
- **Quarterly:** compare the same month a year ago. The retention and recovery programs show up here, because their effect compounds.

## The test

Hand the page to someone who has never seen the store's systems and ask them to explain it. If they can, it is a dashboard a principal will read. If they cannot, simplify it until they can.
